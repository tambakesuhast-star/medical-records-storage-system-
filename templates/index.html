Technical Specification: Medical Records Storage System

Enterprise Cloud Architecture | Security & Data Protection Specification

1. Introduction & Problem Statement

Modern healthcare organizations generate enormous volumes of highly confidential Protected Health Information (PHI), including diagnostic imaging, laboratory blood profiles, surgical summaries, and prescription records. Traditional on-premise storage suffers from severe scalability bottlenecks, elevated operational expenditures, and vulnerability to physical disaster.

To address these critical requirements, this project presents the Medical Records Storage System. The system decouples scalable compute (Cloud Virtual Machine) from highly durable object storage (Azure Blob Storage), while enforcing strict hospital intranet boundary restrictions via IP whitelist filters (192.168.10.0/24) and multi-tier Role-Based Access Control (RBAC).

2. Cloud Resources & Architecture

The solution is architected across three core cloud tiers:

  • Cloud Virtual Machine (Compute): Ubuntu Linux VM hosting the application runtime, reverse-proxy firewall inspection, and RESTful API endpoints.
  • Azure Blob Storage (Object Storage): Container named patient-medical-records providing 99.999999999% (11 nines) of data durability.
  • Cryptographic Vault: Key management provider enforcing AES-256-GCM Server-Side Encryption (SSE) at rest with authenticated data tags and SHA-256 pre-encryption checksums.

3. Security Implementation: IP Restrictions & RBAC

In accordance with enterprise data protection standards:

  • IP Whitelist Enforcement: Clinical endpoints verify the connecting client against authorized subnet 192.168.10.0/24. Any request from external public IPs (e.g. 203.0.113.88) is immediately intercepted and blocked with an HTTP 403 Forbidden status.
  • Doctors Group: Granted full clinical authority to view patient records, upload diagnostic files, view decrypted reports, and formulate clinical assessments.
  • Nurses Group: Authorized to register patients, log vital signs/triage observations, and upload routine lab reports. Restricted from downloading raw confidential records or modifying diagnoses.
  • Admin Group: Segregated from clinical PHI modification; possesses authority to manage firewall rules, configure cloud storage accounts, and inspect audit trails.

4. Conclusion & Demonstrated Results

The implementation fully meets and exceeds all enterprise healthcare data compliance standards. The system demonstrates robust encryption-at-rest with zero plaintext leakage, reliable IP-based boundary enforcement, role-segregated authorization, and comprehensive audit accountability.
